Definir datos de ejemplo para nuestras peticiones es una excelente idea, ya que nos permite probar rápidamente la aplicación durante la fase de implementación. Hasta el momento, contábamos con información generada automáticamente por FastAPI, pero ahora vamos a aprender cómo personalizar esos campos.

Para estos primeros ejercicios, utilizaremos el modelo de Pydantic llamado Task para definir estos ejemplos.

Poder configurar algunos datos de prueba es ideal cuando nuestras entidades van creciendo de tamaño; con esto, ganamos unos pocos segundos cada vez que realizamos pruebas en la API mediante la documentación automática.

Configuración del Modelo con model_config

Para definir estos datos, debemos añadir una configuración especial dentro de nuestra clase. La sintaxis utiliza model_config y el campo json_schema_extra. Sigue este esquema:

  • model_config: Se utiliza para las configuraciones del modelo.
  • json_schema_extra: Es un diccionario donde extenderemos el esquema JSON.
  • examples: Es una lista donde definiremos los ejemplos de la data que queremos mostrar.

Implementación con model_config

Definimos cada uno de los campos que tiene nuestra clase: el id, el name, una description y el status. También podemos definir valores para las etiquetas (tags) pasando un arreglo con ejemplos como "tag 1" y "tag 2".

models.py 

class Task(MyBaseModel):
    ***
    model_config = {
        "json_schema_extra": {
            "examples": [
                {
                "id" : 123,
                "name": "Salvar al mundo",
                "description": "Hola Mundo Desc",
                "status": StatusType.PENDING,
                "tag":["tag 1", "tag 2"],
            ]
        }
    }

Como puedes ver, definimos cada uno de los campos que tiene nuestra clase: el id, el name, la description y el status (usando nuestro StatusType). También incluimos las etiquetas en formato de array. Por supuesto, todos estos valores los puedes personalizar totalmente a tu gusto.

Definición de Relaciones en los Datos de Ejemplo

¿Y qué pasa con las relaciones, como por ejemplo la de categoría? También podemos definirlas fácilmente dentro de nuestro esquema de ejemplos.

Para hacerlo, simplemente añadimos el nombre del campo (en este caso, categoría) y definimos internamente otro diccionario con sus atributos. Por ejemplo, podemos asignarle un id como 123 y un nombre como "cate 1".

Si existen relaciones en la entidad, como lo es en nuestro caso con la relación de tareas basta especificarlas como puedes ver en el siguiente ejemplo:

models.py 

class Task(MyBaseModel):
    ***
    model_config = {
        "json_schema_extra": {
            "examples": [
                {
                "id" : 123,
                "name": "Salvar al mundo",
                "description": "Hola Mundo Desc",
                "status": StatusType.PENDING,
                "tag":["tag 1", "tag 2"],
                "category": {
                    "id":1234,
                    "name":"Cate 1"
                },
                "user": {
                    "id":12,
                    "name":"Andres",
                    "email":"admin@admin.com",
                    "surname":"Cruz",
                    "website":"http://desarrollolibre.net",
                }
                }
            ]
        }
    }

Siguiendo la misma lógica, como puedes apreciar en el código anterior, podemos agregar los datos para el objeto de usuario.  Recuerda que puedes personalizar todos estos valores a tu gusto:

  • Identificador: Un ID de ejemplo.
  • Nombre: Tu nombre o uno genérico.
  • Email: Un correo como admin@admin.com.
  • Surname: El apellido del usuario.
  • Sitio Web: Una URL válida.

Datos de Ejemplo en Parámetros y Body

Además de definir ejemplos en el modelo, también podemos aplicarlos a otros parámetros como el Body, Path, Query, Header, Cookies, formularios o campos (fields).

La estructura es muy similar a la que ya conocemos, pero es importante acotar algo: si definimos un ejemplo a nivel del argumento del método, este sobrescribirá al que se encuentre definido a nivel del modelo.

Implementación de examples en el Parámetro

Para implementarlo, la sintaxis es sencilla. Dentro del parámetro del método, añadimos la propiedad examples, la cual recibe una lista (array) con la data que queremos mostrar. 

# Ejemplo simplificado en un parámetro Body
examples=[
   {
       "id": 4,
       "name": "Hola Mundo",
       "description": "des 2",
       "status": "pending"
   }
]

En este caso, cambié el ID y la descripción. Como aplicamos este cambio para el método PUT, al revisar la documentación interactiva verás que el PUT ahora toma estos nuevos datos en lugar de los del modelo.

Uso de openapi_examples para Múltiples Ejemplos

Si queremos ofrecer un listado de opciones más claro en la documentación, podemos emplear el parámetro openapi_examples. Para ello, debemos estructurar los datos de una manera un poco más detallada que la anterior.

Estructura del Diccionario

A diferencia del método simple, aquí utilizamos un diccionario donde cada clave representa un ejemplo. Dentro de cada ejemplo, definimos los siguientes campos:

Clave de identificación: Un nombre interno (ej. Example1).

  • Summary: El título o etiqueta que aparecerá en el selector desplegable (el label de la opción).
  • Description (Opcional): Una explicación detallada del ejemplo.
  • Value: El diccionario con los datos reales que se enviarán en la petición.

Vamos a definir ahora nuestros ejemplos personalizados: 

openapi_examples={
   "Example1": {
       "summary": "Primer ejemplo",
       "value": {
           "id": 1,
           "name": "Tarea inicial",
           "description": "Descripción del primer ejemplo"
       }
   },
   "Example2": {
       "summary": "Segundo ejemplo",
       "value": {
           "id": 4,
           "name": "Otra tarea",
           "description": "Hola mundo 2",
           "tags": ["etiqueta 4"]
       }
   }
}

Verificación en el Selector

Al guardar y recargar la documentación, notarás que ahora aparece un Select o menú desplegable.

Fíjate que el texto que definimos en el summary es el que se muestra en el listado. Al cambiar entre las opciones, verás cómo varía automáticamente la data del ejemplo que vas a utilizar. Si quieres agregar un tercer o cuarto escenario, simplemente debes duplicar la estructura dentro del diccionario.

Datos de ejemplos desde el argumento

En este apartado, veremos cómo agregar los datos de ejemplo directamente desde los argumentos de las funciones de la API.

También podemos declarar los datos de ejemplo desde los métodos de la API:

O definir un solo valor en la clase: 

class Task(MyBaseModel):
    name: str #= Field(examples=['MyUserAdmin'])

Para que tome este valor, debes de comentar o remover el bloque de ejemplos definidos anteriormente.

Ejemplo simple

Incluso desde las primitivas (como un campo de teléfono de tipo texto), podemos definir datos de ejemplo. Esto mismo lo podemos aplicar si el campo fuera un entero, un booleano o cualquier otro tipo simple que definamos; es decir, casos donde no estemos usando algo compuesto como el modelo de tareas, sino simplemente un texto, un número, etc.

Podemos declarar datos de prueba para los Body(), Path() y Query(); por ejemplo: 

@app.get("/ep_phone/{phone}") # +34 111 12-34-56
def phone(phone: str = Path(pattern=r"^(\(?\+[\d]{1,3}\)?)\s?([\d]{1,5})\s?([\d][\s\.-]?){6,7}$", example="+34 111 12-34-56")):
    return {"phone": phone}

O 

@app.get("/e_phone/") # +34 111 12-34-56
def phone(phone: str = Query(pattern=r"^(\(?\+[\d]{1,3}\)?)\s?([\d]{1,5})\s?([\d][\s\.-]?){6,7}$", example="+34 111 12-34-56")):
    return {"phone": phone}
